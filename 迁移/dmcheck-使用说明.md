# dmcheck · 达梦连接诊断工具（现场使用说明）

迁移程序报「连不上达梦」的时候，用它定位问题。它把连接过程拆成 6 个独立步骤逐个验证，
最后直接告诉你**卡在哪一步、是什么原因、该怎么处理**。

**这个工具是只读的**：只做查询，不写入、不修改、不删除任何数据，可以放心反复运行。

---

## 一、三步跑起来

```bash
# 1. 加执行权限，并把文件名改成短一点（下面的命令都按改完之后的写）
chmod +x dmcheck_linux_amd64
mv dmcheck_linux_amd64 dmcheck

# 2. 编辑同目录的 dmcheck.env，填成现场的地址和账号密码
vi dmcheck.env

# 3. 运行
./dmcheck
```

跑完屏幕会打印完整报告，同时把同一份内容存成 `dmcheck-report.txt`，方便回传。

> 目录里放这三个文件就够了：`dmcheck`、`dmcheck.env`。报告文件会自动生成。
>
> 如果 `chmod` 提示权限不足，或者双击没反应，见文末「常见问题」。

---

## 二、报告怎么看

前后都不用细看，**直接看最后的「诊断结论」**，长这样：

```
════════════════════════════════════════════════════════════════
 诊 断 结 论
════════════════════════════════════════════════════════════════

  ✗ [阻断] TCP 连接被拒绝（端口没有服务在监听）
      原始错误：dial tcp 10.8.19.133:5236: connect: connection refused

      处理建议：
        1) 确认达梦实例已启动
        2) 确认端口号正确：达梦默认 5236，注意不要写成旧环境的 5237

────────────────────────────────────────────────────────────────
 结论：连接未打通，共 1 项阻断问题。请按上面的处理建议逐项排查。
════════════════════════════════════════════════════════════════
```

三种标记的含义：

| 标记 | 含义 |
| --- | --- |
| `✓ [正常]` | 这一项没问题 |
| `! [警告]` | 不影响连通，但建议确认 |
| `✗ [阻断]` | 就是它导致连不上，按建议处理 |

**判断连接是否成功**，看最后一行结论，或者看退出码：`echo $?` 返回 `0` 是通了，返回 `1` 是不通。

## 三、常见结论与处理办法

| 屏幕上出现的结论 | 原因 | 怎么办 |
| --- | --- | --- |
| 找不到可用的配置文件 | 配置文件名或位置不对 | 确认 `dmcheck.env` 和 `dmcheck` 在同一个目录，文件名不能是 `dmcheck.env.txt` |
| 配置项缺失（缺少 DM_HOST / DM_USER） | 配置里没填 | 打开 `dmcheck.env` 补齐 |
| 有配置行的值被解析器改写 | 密码里含 `#`，且 `#` 前有空格 | 见下面「密码里有特殊字符怎么办」 |
| 主机名解析失败 | `DM_HOST` 填了主机名但本机解析不了 | 直接改成 IP 地址 |
| TCP 连接被拒绝 | 端口上没有服务 | 确认达梦已启动；确认端口写对了（达梦默认 `5236`） |
| TCP 连接超时 | 网络不通或被防火墙丢包 | 确认本机在内网或 VPN 已连上；确认防火墙放行 |
| 用户名或密码错误 | 见下节，分两种情况 | 见下面「密码里有特殊字符怎么办」 |
| 账号已被锁定 | 反复用错密码触发锁定 | 联系 DBA 解锁；解锁前不要再重试 |
| 模式 XXX 不存在 | `DM_SCHEMA` 填错了 | 报告里有该实例全部模式名，照着改，或直接留空 |
| 源表 XXX 不存在 | 连到了不存放源表的实例 | 确认 `DM_HOST` 是不是源库地址 |
| 没有发现任何问题 | 一切正常 | 可以直接去跑迁移程序了 |

## 四、密码里有特殊字符怎么办（最容易被卡住的一类）

如果你的密码里含 `@` `?` `:` `#` `%` 空格 等字符，可能会一直报「用户名或密码错误」，
**但密码本身其实是对的**。报告里会出现这样的结论：

```
  ✗ [阻断] 根因确认：密码被 URL 转义导致认证失败

      同一份账号密码，
        用主程序的方式（URL 转义）→ 认证失败
        用字面量方式（不转义）→ 认证成功
```

看到这条，**不是现场的问题，是迁移程序的缺陷**，请把报告整体回传给开发方。
在修复版本发来之前，可以让 DBA 临时把密码改成不含上述特殊字符的（例如纯字母数字组合），
就能先跑起来。

诊断过程不会瞎试密码：只有确认密码里含特殊字符时，才会额外做一次登录尝试，
避免因反复失败导致账号被锁。

## 五、常用参数

不带任何参数直接跑就行。需要时会用到这几个：

| 参数 | 说明 |
| --- | --- |
| `-env /路径/文件` | 指定配置文件。默认自动找当前目录的 `dmcheck.env` |
| `-pass '真实密码'` | 临时指定密码，**不改配置文件**。用来绕开配置直接验证密码本身对不对 |
| `-user 用户名` | 临时指定用户名 |
| `-host 10.8.19.133` | 临时指定地址 |
| `-port 5236` | 临时指定端口 |
| `-table 模式.表名` | 指定要检查的源表名，默认检查两张迁移用的源表 |
| `-show-secret` | 报告里显示账号密码明文（现场核对自己有没有输错时用），用完记得删掉报告 |
| `-config-only` | 只检查配置，不做任何网络连接。适合在不能联网的机器上先核对配置 |
| `-out 报告.txt` | 指定报告文件名；填 `-` 表示只在屏幕显示、不存文件 |

例子：

```bash
# 怀疑密码输错了，直接传一次真实密码试试
./dmcheck -pass '现场的真实密码'

# 只想核对配置文件写得对不对，不连网
./dmcheck -config-only

# 源表名和默认不一样时
./dmcheck -table DLPDATA.did_system_sync_user
```

## 六、常见问题

**双击或 `./dmcheck` 提示 `Permission denied`**
先执行 `chmod +x dmcheck`。如果是从 Windows 拷过来的，还可能要执行 `sed -i 's/\r$//' dmcheck.env`
清掉行尾的回车符（配置文件从 Windows 编辑过就要做这一步）。

**提示 `cannot execute binary file` 或 `Exec format error`**
下错架构了。在目标机器上执行 `uname -m`：显示 `x86_64` 用 `amd64` 版本，显示 `aarch64` 用 `arm64` 版本。

**改了 `dmcheck.env` 但报的还是旧地址**
报告第 1 步会把「所有候选配置文件」列出来，并标明实际读的是哪一个。看那里就知道改对文件没有。

**想让报告里带上密码方便核对**
加 `-show-secret`。注意这样报告里会有明文密码，核对完请把报告文件删掉。

---

## 七、把什么回传给开发方

出现问题时，请把 **`dmcheck-report.txt` 整个文件**发回来，不要只截取报错那一行。
报告里带了配置解析结果、网络情况、驱动版本和库内对象，这些信息能省掉好几轮来回沟通。

报告里默认不包含明文密码（密码显示为 `******` 和字符数），直接发是安全的。
如果用了 `-show-secret`，发之前请先把报告里的密码删掉。
