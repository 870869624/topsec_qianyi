## 关键技术结论（重要，后续复用）

### 1. Mongo 目标库位置
`pkg/model/model.go:45-46` → `identity` 库的 `user` / `organization` 集合。
BSON 字段定义以 `pkg/model/identity/usertypes.go`、`orgtypes.go` 为准
（`mongo表结构/*.txt` 里的说明已过时，例：user 的 txt 漏了 `tw_insert_time`）。

### 2. 类型不一致必须转换
- 达梦 `user_status` 是 `INT`，但 `identity.User.UserStatus` 是 `string`
- 达梦 `sort_no` 是 `INT`，但 `identity.Organization.SortNo` 是 `string`
→ 必须转成字符串写入，否则应用侧 BSON 反序列化会因类型不匹配报错。

### 3. 字段名拼写差异
达梦 `linkeman_email` → Mongo `linke_man_email`（目标少一个 n）。

### 4. 达梦标识符大小写
DDL 中表名和多数列为小写加引号（`"uid"`），但 `"JOB"`、`"PASSWORD"` 是大写加引号。
SQL 里必须严格按 DDL 大小写加双引号，否则报表不存在。
脚本提供 `-dm-case as-is|upper|lower` 兜底。

### 5. 达梦 Go 驱动
- 用 `github.com/godoes/gorm-dameng`，只需 blank import 它的 `dm8` 子包即可注册
  `database/sql` 的 `"dm"` 驱动（`dm8/p.go:26 sql.Register("dm", ...)`），不必引入 gorm。
- DSN：`dm://user:pass@host:port?schema=X&rowPrefetch=500&connectTimeout=30000&appName=...`
- `rowPrefetch` 影响每批预取行数，直接关系到流式读取的内存占用。
- 该驱动在 `init()` 里往默认 FlagSet 注册了 `DM_HOME`，会污染 `-h` 输出，
  脚本里用自定义 `flag.Usage` 过滤掉。
- 驱动返回的 TIMESTAMP 可能是 `time.Time` / `[]byte` / `string`，
  标准库 `sql.NullTime` 遇到字符串会直接报错 → 自定义 `syncbase.NullTime` 兼容多种表示。

### 6. 大表读取策略
默认走「ROWNUM 分页」（`-page-size 20000`）而不是单次流式查询，内存绝对可控；
如需最快速度可 `-page-size 0` 切流式。

### 7. drop 会丢索引 → 已做快照重建
`-clean drop` 删除集合会连同索引一起删掉。脚本在 drop 前用 `CaptureIndexes`
把索引定义快照下来，数据写完后 `RestoreIndexes` 原样重建。
若要保留索引，也可直接用 `-clean delete`（DeleteMany，保留集合结构）。

## 补充：Linux 交叉编译支持（同日）

新增 `demo/build.sh` 与 `demo/README.md`，解决「怎么编译成 Linux 可执行文件并部署」。

### 交叉编译是干净的

达梦驱动 `godoes/gorm-dameng` 与 `mongo-driver` **均为纯 Go 实现**（无 `import "C"`），
所以 `CGO_ENABLED=0` 即可静态链接，产物不依赖目标机 glibc 版本，
不会出现 `GLIBC_2.xx not found`。无需 Docker 或交叉工具链。

### 构建命令（在模块根目录执行，即 go.mod 所在目录）

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
  go build -trimpath -ldflags "-s -w" -o migrate_user ./demo/migrate_user/
```

- 包路径必须是 `./demo/migrate_user/`，在 demo/ 里直接 `go build ./migrate_user` 会因找不到 go.mod 失败。
- `-s -w` 去符号表：体积 **17MB → 12MB**。
- 实测通过：amd64（ELF e_machine `0x3e`）、arm64（`0xb7`）均编译成功。
- `build.sh` 用法：`bash demo/build.sh [linux/amd64 linux/arm64 ...]`，产物落 `demo/dist/`。

### 部署形态（已实测验证）

程序从 cwd 与 cwd/demo 逐级向上查找 `.env`，因此下列布局**不带任何参数**即可运行：

```
/opt/dm2mongo/
├── migrate_user / migrate_org
├── .env          # 权限建议 600
└── logs/         # **必须手动创建**
```

- 已实测：独立目录放 `.env` + 二进制，运行后正确命中该 `.env`，密码脱敏显示正常。
- ⚠️ **`logs/` 目录不会自动创建**（`NewLogger` 用 `os.OpenFile`，不建父目录），
  必须先 `mkdir -p logs`，否则报「打开日志文件失败」。
- 中断行为：在分页/批次边界处停止（`runner.go` 的 `flush()` 里 `select ctx.Done()`），
  不会留半截文档；`drop` 模式下中断后直接重跑即可。

已在项目根 `.gitignore` 追加 `/demo/dist/`、`/demo/migrate_user(.exe)`、`/demo/migrate_org(.exe)`。

## 补充二：连接配置层重构（同日，.env 换格式后）

`.env` 改成了 `HOST`/`PORT` 分离式，原连接代码只认 `DM_JDBC_URL`/`MONGO_URL`，会直接报错，因此重写了配置层。

### 新的 .env 格式契约（唯一支持的写法）

```ini
DM_HOST= / DM_PORT= / DM_USER= / DM_PASS= / DM_SCHEMA(选填)
MONGO_HOST= / MONGO_PORT= / MONGO_DB= / MONGO_USERNAME= / MONGO_PASSWORD= / MONGO_AUTH_SOURCE(选填)
```

**不再支持** `DM_JDBC_URL` / `DM_URL` / `MONGO_URL` / `MONGO_URI` 这类连接串写法（已整体删除解析代码）。
默认值：`DM_PORT=5236`（注意不是 5237）、`MONGO_PORT=27017`、`MONGO_DB=identity`、`MONGO_AUTH_SOURCE=admin`。

### 重构要点

- **API 收敛**：5 个导出符号（`Env`/`LoadEnv`/`LoadEnvAuto`/`NewDMConfig`/`NewMongoConfig`）
  → 2 个（`Config`/`LoadConfig`）。`Env` 改为不导出的内部类型 `env`。
- **删除的难维护逻辑**：`parseDMURL`（手写 jdbc:dm:// 解析）、`injectMongoCredential`
  （URL 往返解析 + 账号注入，其中有「URI 自带账号就提前 return 导致不补 authSource」的隐患）、
  `findUp`、`envKeys`/`dbConfigKeys` 两个白名单。
- **环境变量覆盖改为前缀匹配**：凡是 `DM_*` / `MONGO_*` 的系统环境变量都覆盖同名项，
  不再需要维护白名单，新增配置项自动生效。
- **Mongo 连接改为结构化**：`OpenMongo` 用 `SetHosts` + `options.Credential`，
  不再手工拼 `mongodb://` 字符串，彻底避免密码含 `@ : /` 时拼接出错。
- **`DM_SCHEMA` 语义变更**：留空时**不再**默认取 `strings.ToUpper(User)`，
  而是不下发 `schema` 参数（由达梦沿用登录用户默认模式）。
  原因：新 .env 用 `SYSDBA` 登录，若沿用旧逻辑会把默认模式强制设为 `SYSDBA`，
  与表实际所在的 `DLPDATA` 不符，属于误导性行为。
- **`SafeDSN` 曾一度打印明文密码**（`dm://user:PASSWORD@host`），已改回 `***`。
  任何日志函数都不得输出明文密码。
- `LoadEnv` 支持 `DM_USERNAME`/`DM_PASSWORD`/`MONGO_USER`/`MONGO_DATABASE` 等少量别名，
  但主键名以新 .env 为准。

### ⚠️ 重要发现：当前 .env 指向的达梦实例里没有源表

`10.8.19.133:5236`（用户 SYSDBA）**可达且连接成功**，但里面：

- 模式只有 `SYS / SYSAUDITOR / SYSDBA / SYSSSO / BACKUP / CTISYS / DMDLP`
- **没有 `DLPDATA` 模式**，也没有 `did_system_sync_user` / `did_system_sync_org` 表
- `BACKUP` 模式有 107 张表，表名形如 `admin-system.users`、`bff_soc-bff_user_user`，
  是 **MongoDB 集合备份到关系库**的命名风格，判断这是一套 DLP 系统的备份库

→ 跑 `-count-only` 会报 `Error -2103 无效的模式名[DLPDATA]`。
**需要用户确认真实源库地址**，或确认源表是否尚未同步到该实例。

`-dm-table SYS.SYSOBJECTS -count-only` 用达梦自带系统表当靶子，
实测返回 1051 条，可证明「配置 + 网络 + 账号」完全正常。已写入 README。
